### **1. Objective**
In a mature DevOps organization, humans don't run `kubectl apply`. If a human can change the cluster manually, the cluster is "unstable." Instead, we use **GitOps**. The Git repository becomes the "Source of Truth," and a controller inside the cluster ensures the live state matches the code.

**The Goal:** You will install **ArgoCD**, the leading GitOps tool. You will connect it to your GitHub repository and watch as it automatically detects your YAML changes and "pulls" them into the cluster. This is the end of manual deployments.



---

### **2. The Scenario**
Your team is tired of "Configuration Drift" (where someone changes a setting manually and forgets). You've been tasked with setting up a "Self-Healing" pipeline. If someone deletes a pod or changes a service manually, ArgoCD should notice within seconds and revert the change back to what’s in Git.

---

### **3. Part 1: Installing ArgoCD**
ArgoCD runs as a set of pods in its own dedicated namespace.

1.  **Create the Namespace:**
    ```bash
    kubectl create namespace argocd
    ```
2.  **Install ArgoCD:**
    ```bash
    kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
    ```
3.  **Wait for Readiness:**
    ```bash
    kubectl wait --namespace argocd \
      --for=condition=ready pod \
      --selector=app.kubernetes.io/name=argocd-server \
      --timeout=90s
    ```

---

### **4. Part 2: Accessing the Dashboard**
By default, the ArgoCD API server is not exposed externally.

1.  **Port-Forward the UI:**
    ```bash
    kubectl port-forward svc/argocd-server -n argocd 8080:443
    ```
2.  **Get the Initial Password:** The default username is `admin`. The password is autogenerated and stored in a secret.
    ```bash
    kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d; echo
    ```
3.  **Login:** Open your browser to `https://localhost:8080` (bypass the SSL warning) and log in with `admin` and that password.

---

### **5. Part 3: Linking the Git Repo (The "Application")**
We will tell ArgoCD to "watch" your `devops-essentials` folder on GitHub.

1.  **In the ArgoCD UI:** Click **+ New App**.
2.  **Configure General Settings:**
    * **Application Name:** `my-first-gitops-app`
    * **Project:** `default`
    * **Sync Policy:** `Automatic` (Check 'Prune Resources' and 'Self-Heal').
3.  **Configure Source:**
    * **Repository URL:** Paste your GitHub Repo URL.
    * **Revision:** `HEAD` (or `main`).
    * **Path:** `kubernetes/` (or wherever your YAMLs live).
4.  **Configure Destination:**
    * **Cluster URL:** `https://kubernetes.default.svc`
    * **Namespace:** `default`
5.  **Click Create.**

---

### **6. Part 4: The GitOps Magic (The Test)**
Now, let's see why this is better than manual deployments.

1.  **Modify Git:** Go to GitHub and edit your `deployment.yaml` (e.g., change `replicas: 2` to `replicas: 4`). Commit the change.
2.  **Observe ArgoCD:** Within 3 minutes (or if you click "Refresh"), ArgoCD will turn yellow ("OutOfSync") and then green ("Synced").
3.  **Check the Cluster:**
    ```bash
    kubectl get pods
    ```
    *You should see 4 pods running without you ever touching the CLI.*
